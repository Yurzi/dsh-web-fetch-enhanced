# v0.0.11

## 配置版本与自动迁移

- 新增插件局部的 `schemaVersion`，当前格式版本为 `1`，独立于 npm 包版本、DSH 版本及表单 revision。
- 现有无版本配置和显式 v0 配置读取时自动迁移到 v1，无需手动补字段；v1 只引入版本标识，不改变白名单授权及现有字段语义。
- 新增逐版本迁移入口，覆盖直接 `Config(raw)`、Cordis Standard Schema 校验和 `createProvider(raw)`。迁移深克隆输入，保留未知字段及显式空数组，完整校验后才用于运行时配置。
- 非法版本和高于当前支持范围的配置明确报错，不静默降级或回退默认配置。
- 保留对象 schema 元数据、浏览器表单序列化和 Loader volatile 热更新行为；版本字段不作为白名单表单可编辑字段。
- 更新中英文说明、配置示例及[配置迁移设计](https://github.com/Yurzi/dsh-web-fetch-enhanced/blob/v0.0.11/docs/config-versioning.zh-CN.md)。

## 升级与边界

DSH 支持范围仍为 `>=0.2.0-rc.2 <0.3.0-0`，依赖基线不变。按照现有插件管理流程升级到 `dsh-web-fetch-enhanced@0.0.11`，升级前备份 Profile 配置，按部署方式重新加载 Host。旧配置可直接读取，无需手动设置 `schemaVersion`。

本版本只做**运行时内存迁移**，不自动改写用户文件，不向其他 Profile 复制授权，也不读取旧全局设置。后续字段改名须同步设计表单写入与分层持久化迁移，不能仅靠读取转换；需要改变授权范围的歧义配置不应无感自动处理。

- `pnpm run check`：类型检查、lint、Host / Client 构建、测试及 publint 发布包校验通过。
- 14 个测试文件、126 项测试通过，包含 21 项迁移测试及无版本 / v0 / v1 的 Loader 启动与热更新回归。
- 没有修改运行中的用户 Profile；本地测试不等同于浏览器端到端验收。

## English

v0.0.11 introduces plugin-owned configuration schema version 1 and immutable, sequential runtime migrations. Unversioned and explicit v0 configurations are automatically normalized before validation; invalid or future versions are rejected. Existing authorization semantics, explicit empty overrides, browser forms, and Loader live updates are preserved. Migration runs in memory only and does not rewrite user files. Future field renames must also address form writes and layered persistence. DSH compatibility remains `>=0.2.0-rc.2 <0.3.0-0`. All 126 tests across 14 files and the full package checks pass.
