# v0.0.12

## 自定义 User-Agent

- 插件详情页新增独立的 **User-Agent** 编辑区，支持保存、放弃修改和重置为继承值；UA 操作只修改当前 Profile 的 `userAgent`，不改变 CIDR 或域名白名单。
- 默认 UA 与官方 DSH HTTP provider 对齐：`deepseek-harness/0.0.1 (+https://github.com/deepseek-ai)`，不默认使用 Chromium 或其他浏览器 UA。
- 复用 Loader volatile 热更新：保存成功后下一次 `web_fetch` 生效，无需重启。正在执行的请求保留原配置快照；直连、代理和同源重定向每一跳使用同一配置 UA。
- 独立表单保留 Profile revision 冲突保护；保存失败或连接错误不清除草稿、不显示为成功，支持只读状态与放弃重试。

## 校验与兼容性

- 浏览器与 Host 共用请求头字符校验，拒绝 CR/LF、其他非法控制字符及非 Latin-1 字符；补齐直接创建 provider 的 UA 校验，并修复末尾换行可能通过正则校验的问题。
- 未显式配置 UA 的用户改用官方默认值；已有 UA 覆盖（包括旧产品 UA 与空字符串）不被自动改写。
- 空字符串仍表示显式发送空 UA 请求头，**不等于恢复默认值**。重置操作移除当前 UA 覆盖，恢复底层 Profile 值；没有继承值时使用官方默认。
- 配置格式不变，`schemaVersion` 仍为 `1`；DSH 支持范围仍为 `>=0.2.0-rc.2 <0.3.0-0`，依赖基线不变。
- 不增加模型侧工具参数、不发送 Cookie 或 Authorization、不改变地址授权与重定向安全边界。修改 UA 不提供浏览器 TLS 指纹、JavaScript 执行或验证码处理，也不保证绕过反爬。

## 升级

按现有插件管理流程升级到 `dsh-web-fetch-enhanced@0.0.12`。升级前备份 Profile 配置，升级后按部署方式重新加载 Host 和客户端；之后修改 UA 不需要重启。入口为 **插件 → dsh-web-fetch-enhanced → User-Agent**。

详细用法见[自定义 UA 说明](https://github.com/Yurzi/dsh-web-fetch-enhanced/blob/v0.0.12/README.md#自定义-user-agent)。

## 验证

- 类型检查、type-aware lint、Host / Client 构建、全部 15 个测试文件的 156 项测试、覆盖率门槛与发布包检查通过。
- 新增 30 项回归测试，覆盖默认值、非法字符、表单保存/重置/冲突/只读、Loader 热更新，以及直连和代理的重定向请求头。
- 本地 pnpm 缓存数据库不可用，等价检查使用本地工具执行；发布包检查使用 `publint --pack npm`。
- 没有修改运行中的用户 Profile；本地测试不等同于浏览器端到端验收。

## English

v0.0.12 adds a Profile-scoped User-Agent editor with independent save, discard, and restore-inherited actions. The default now matches official DSH: `deepseek-harness/0.0.1 (+https://github.com/deepseek-ai)`, not a browser UA. Existing explicit overrides, including empty strings, are preserved. Live changes apply to the next fetch without restarting; direct requests, proxy requests, and same-origin redirects use the configured UA. Shared browser/Host validation rejects invalid header characters and trailing newlines. UA actions never modify address allowlists, and stale writes remain revision-fenced. Configuration schema version remains 1 and DSH compatibility remains `>=0.2.0-rc.2 <0.3.0-0`. All 156 tests across 15 files, coverage thresholds, builds, and package checks pass. Changing UA does not guarantee bypassing bot detection.
