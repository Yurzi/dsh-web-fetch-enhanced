# v0.0.9

## 兼容性与版本要求

- 最低支持 DeepSeek Harness **0.2.0-rc.1**（上游标准 SemVer 写法），插件版本由 0.0.8 升至 **0.0.9**。
- `engines.dsh` 与全部 9 个 DSH peer 范围统一为 `>=0.2.0-rc.1 <0.3.0-0`；不再支持 DSH 0.1.x。
- DSH 直接开发依赖固定为 `0.2.0-rc.1`，同步更新 pnpm 锁文件及精确版本的 `minimumReleaseAgeExclude`。其他直接依赖版本声明不变。
- 使用 `<0.3.0-0` 而非 `<0.3.0`，避免 Host 在 `includePrerelease: true` 下意外接受未来 0.3.0 的 Alpha / RC；后续 minor 版本需重新评估。

## 上游 0.1.7-rc.2 → 0.2.0-rc.1 影响评估

以所提供的升级分析为线索，独立核对上游 `dsh-v0.1.7-rc.2` → `dsh-v0.2.0-rc.1`（目标提交 `4878cdabd87d4041bdaff61d04c966883b9fd07a`）源码差异及本插件实际调用点。结论：**未发现需要修改本插件业务代码的破坏性接口变更，主要工作是更新版本约束与验证基线；升级风险较低，但不代表所有部署场景均已验证。**

| 上游变化 / 集成点 | 核对结果与影响 |
| --- | --- |
| 抓取与安全传输 | 上游 `web`、`web-fetch-http`、`tool-web`、`http-proxy`、`timeout` 相关包仅版本号变化，源码未变；`WebFetchProvider` / `WebFetchResult` / `WebError`、代理路由及 deadline 接口无需迁移。插件的 SSRF、DNS 固定、重定向和资源限制逻辑不变。 |
| 动态系统提示词 | `system-prompt` 相关包仅版本号变化；白名单授权 section、`system-prompt/change` 和 Loader volatile 配置更新机制继续沿用。 |
| 插件管理页交互更新 | 上游新增安装输入清洗、IME 防误提交、刷新 Toast 及产品分析调用，但 `plugins.bundle.config` 槽位仍在，`slot-contract.ts` 未变。本插件不调用安装控制器或遥测接口。 |
| 配置表单、locale、renderer、slots、ModuleLoader | 对应包仅版本号变化；`configForms.get`、订阅 / 快照、带 revision 的 `mutate`、Client factory 注册方式无需调整。 |
| Schedule / time-context 从 Web 默认组合移除 | 本插件不使用这些服务，也未 patch 被移除的行；所需 `web`、`web-fetch-http` 行仍在 base bundle，现有发布 / 源码 patch 不变。用户自行叠加的旧 schedule patch 需单独迁移。 |
| OTel / 产品埋点 / 日志上传控制 | 本插件不直接初始化 OTel SDK 或依赖 `ctx.otel`；无新增遥测依赖。自定义 Host 组合应自行满足上游遥测插件的依赖。 |
| 工具事件失败恢复 | 本插件只注册 fetch provider，不自行写入 `tool/call` / `tool/result` 或更改 turn / step，因此没有自定义事件格式迁移。 |
| 原生命令窗口参数、聊天详细视图默认值 | 本插件不调用 `runNativeCommand`，也不维护聊天消息渲染；对白名单配置和抓取没有直接影响。 |
| 原生 DeepSeek 搜索新增账号鉴权 | 属于 `web_search` 的 provider 变化；本插件只替换 fetch provider，不禁用搜索 provider，也无需接入 `deepseekAccount`。 |

### SemVer 边界说明

旧范围 `>=0.1.7-rc.2 <0.2.0` 对 `0.2.0-rc.1` 的行为需区分：

- 默认 `semver.satisfies`（包管理器常用语义）返回 **false**：原因是跨版本预发布排除规则，并非 `0.2.0-rc.1` 大于或等于 `0.2.0`。
- 上游 Host 的 `evaluatePluginCompatibility` 使用 `includePrerelease: true` 检查 DSH peers，该旧范围对 `0.2.0-rc.1` 返回 **true**；不能笼统认定 Host 一定拒绝旧插件。
- 仅把上界放宽到 `<0.3.0`、保留旧下界，仍不能保证包管理器默认规则接受新 RC。因此本次显式设置下界 `0.2.0-rc.1`，并同时更新 engine、peers 与开发依赖。
- 新范围在两种语义下均接受 `0.2.0-rc.1`、同一版本的后续 RC 和 0.2.x 正式版，拒绝旧版及 0.3.0 预发布 / 正式版。后续其他 patch 的预发布版本仍受包管理器默认预发布规则约束，不能据此宣称已验证所有未来 RC。

## 升级方式

1. 先升级 Host 至 DSH `0.2.0-rc.1` 或支持范围内的更新版本，再升级插件至 v0.0.9。
2. 从 v0.0.8 升级无需迁移配置，现有 Profile 白名单与资源限制继续生效。更早版本的全局配置按[历史迁移说明](<../migration-0.1.7-rc.1.zh-CN.md>)处理，目标 Host 仍须满足本次版本门槛。
3. 升级后重启 Host 并刷新 Web 页面。日常白名单保存仍无需重启。

## Client 打包修复

- 将浏览器 Client 产物改为明确的 `.cjs` 扩展名，并同步 `exports["./client"].default`、发布文件列表及构建配置，修复 ESM 包内 CJS 产物使用 `.js` 引发的 publint 格式警告。Host 仍为 ESM，公开 `./client` 子路径与类型声明路径不变。
- 保留 `window.__ModuleLoader__.load({ id, factory })` 包装，不将 Client 改成浏览器原生 ESM。上游根据 manifest 中的 `./client` 导出定位文件，再通过既有 `client.js` 资源 URL 和 JavaScript MIME 提供内容，因此实际文件扩展名变化不要求修改宿主路由。
- 增加导出 / 发布文件契约测试，并在 ModuleLoader 测试中解析公开入口，确保验证的是新产物而非残留旧文件。

- `pnpm run check` 通过：类型检查通过，lint 为 0 警告 / 0 错误，Host / Client 构建成功，13 个测试文件、101 项测试全部通过，包含构建产物的 ModuleLoader 注册测试。
- `pnpm run test:coverage` 通过：语句覆盖率 98%，分支 95.48%，函数 100%，行 99.54%，逐文件阈值达标。
- `pnpm install --store-dir .pnpm-store --frozen-lockfile --offline` 通过，锁文件与声明一致；未顺带升级非 DSH 依赖。
- 版本门槛测试覆盖默认 semver 与 `includePrerelease: true` 两种规则，检查 engine / peers 一致性及上下界。

`pnpm exec publint --strict` 通过并输出 **All good!**，无警告或错误。修复通过明确 Client 产物的 `.cjs` 扩展名消除格式歧义，保留 DSH ModuleLoader factory 契约；公开入口解析和新产物注册 / 执行测试均通过。未执行真实浏览器端到端验收，也未重启或修改运行中的用户 Profile；没有执行 npm 发布或创建 Git tag。

## English

v0.0.9 raises the minimum DSH version to **0.2.0-rc.1**. All DSH peer ranges and the engine range are `>=0.2.0-rc.1 <0.3.0-0`, and direct DSH development dependencies are pinned to the tested release. The upstream release diff shows no breaking interface change requiring plugin implementation changes: fetch, proxy, timeout, prompt, configuration forms, and the bundle configuration slot remain compatible. The plugin does not use the changed schedule, telemetry, native-command, tool-event, or search-auth APIs. The Client artifact now uses an explicit `.cjs` extension while preserving the public `./client` subpath and DSH ModuleLoader factory contract. Strict publint validation is warning-free, and all 101 tests pass. No configuration migration is required from v0.0.8. Upgrade the Host first, then restart it and refresh the browser after upgrading the plugin.
