# v0.0.10

## 兼容性与依赖基线

- 最低支持 DeepSeek Harness **0.2.0-rc.2**（上游标准 SemVer 写法），插件由 0.0.9 升至 **0.0.10**。
- `engines.dsh` 与全部 9 个 DSH peer 范围统一为 `>=0.2.0-rc.2 <0.3.0-0`；不再支持 rc.1 或更早版本。上界同时排除未经评估的 0.3.0 预发布 / 正式版。
- DSH 直接开发依赖固定为 `0.2.0-rc.2`，同步更新 pnpm 锁文件及精确版本的 `minimumReleaseAgeExclude`，避免不同代 DSH 包混装。
- 与 rc.2 上游一致的其他最低版本保持不变：Cordis `4.0.4`、Cordis Loader `1.0.5`、Schemastery `3.18.4`、ipaddr.js `2.5.0`、Undici `8.10.0`。不顺带升级无关工具链。

## 上游 rc.1 → rc.2 影响核对

结合两份升级评估报告，独立核对上游 `dsh-v0.2.0-rc.1` → `dsh-v0.2.0-rc.2`（目标提交 `639ed015397290b3745d163aafe02ffee4aa3f84`）以及本插件的实际调用点。

| 集成点 / 上游变化 | 本插件影响 |
| --- | --- |
| Fetch、代理、超时、系统提示词 | 对应公开接口源码未变，无需修改 provider 或安全传输逻辑。默认拒绝、DNS 全答案校验 / 连接固定、同源重定向复核和资源限制保持不变。 |
| 插件管理与配置表单 | `plugins.bundle.config`、ConfigForms、locale 和 slots 契约未变。上游安装提示和页面样式变化不要求迁移白名单表单。 |
| Renderer | 上游将 factory 祖先集合改为 memoized 值；本插件不替换 renderer 内部实现，保留现有 ModuleLoader factory 和 `.cjs` Client 入口。 |
| Undici Dispatcher 类型漂移 | 插件与 rc.2 HTTP proxy / fetch 使用相同的 `^8.10.0` 范围。增加测试核对最低版本及安装后的解析路径，避免在开发依赖中引入两套 Dispatcher 类型；不使用类型断言掩盖冲突。 |
| Timed 问答、Gateway、侧栏 / OpenInApp props | 本插件不实现这些接口，也不将提问的 pending / 超时当作网络授权。无需相关迁移。 |
| pi-ai 模型目录、提醒 framing、终端及 Windows ACL | 本插件不选择模型、不创建提醒、不发现 Shell、不包装 ACL 脚本；不机械替换模型 ID 或改变外部内容的信任语义。 |

结论：本次无需重写业务代码或迁移现有配置；重点是提升版本门槛、统一依赖和回归验证。

## 升级方式

1. 先将 Host 升级至 DSH `0.2.0-rc.2` 或支持范围内的更新版本。
2. 备份 / 记录当前 Profile 中的白名单和资源限制。rc.2 的插件管理不支持已安装包直接自动升级，需先卸载再安装：

```bash
dsh plugin --profile web remove dsh-web-fetch-enhanced
dsh plugin --profile web add dsh-web-fetch-enhanced@0.0.10
```

3. 按部署方式重启 Host，刷新 Web 页面，并核对目标 Profile 的配置。配置结构没有变化，但不要假设卸载重装一定保留所有 Profile 覆盖值；必要时从备份恢复。日常保存白名单仍无需重启。
4. Desktop Profile 应先至少启动一次桌面端，以初始化 Profile，再按上游桌面插件管理流程安装。

## 验证

在 Node `26.10.0`、pnpm `11.7.0` 下使用 rc.2 npm 依赖完成验证：

- `pnpm run check` 通过：类型检查通过，lint 0 警告 / 0 错误，Host / Client 构建成功，13 个测试文件、**102 项测试全部通过**，包括 ModuleLoader 产物注册和代理 / DNS / SSRF 回归。
- `pnpm run test:coverage` 通过：语句 **98%**、分支 **95.48%**、函数 **100%**、行 **99.54%**，逐文件阈值达标。
- `pnpm exec publint --strict` 通过，输出 **All good!**，无格式或导出警告。
- `pnpm install --store-dir .pnpm-store --frozen-lockfile --offline` 通过，锁文件与依赖声明一致；全部 16 个 DSH 直接 / 传递包对齐 rc.2，未升级无关依赖。
- SemVer 回归在默认规则与 `includePrerelease: true` 下均拒绝 rc.1、接受 rc.2 / 同版本后续 RC 与 0.2.x 稳定版，并拒绝 0.3.0 预发布 / 正式版。Undici 最低版本和解析路径一致性测试通过，无 Dispatcher 类型冲突。

没有修改或重启运行中的 DSH Profile，不将单元 / 契约测试等同于真实浏览器或 Desktop 端到端验收。

## English

v0.0.10 raises the minimum DSH version to **0.2.0-rc.2**. All nine DSH peer ranges and the engine range are `>=0.2.0-rc.2 <0.3.0-0`; direct DSH development dependencies are pinned to rc.2. Other dependency floors already match upstream, including Undici **8.10.0**. A regression test checks the transport dependency range and shared installed Dispatcher type source. The upstream public fetch, proxy, timeout, prompt, and configuration-form contracts remain compatible, so no provider rewrite or configuration-schema migration is needed. Back up Profile settings, upgrade the Host first, remove and reinstall the plugin using the rc.2 plugin manager, then restart the Host and refresh the browser. Live Profile changes and browser / Desktop end-to-end validation are outside this release verification.
