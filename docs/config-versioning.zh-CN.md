# 插件配置版本与迁移设计

## 结论与范围

配置版本是合理且必要的兼容边界，但必须独立于 npm 包版本、DSH 版本和表单并发 revision。只有配置结构或含义变化时才递增；普通修复和不改变旧语义的可选字段不必升版。

本次实现插件局部的运行时自动迁移，不修改宿主、不扫描其他 Profile、不读取旧全局设置、不自动改写用户文件。v1 与原有字段语义相同，仅引入版本标识。

## 配置契约

```yaml
- id: web-fetch-enhanced
  config:
    schemaVersion: 1
    allowCidrs: []
    allowHostnames: []
```

- `schemaVersion` 属于插件自己的 `config`，不是 Cordis entry 或 Profile 的版本。
- 缺失或 JavaScript `undefined` 表示历史 v0；显式 `0` 同样支持。`null`、字符串、负数、小数和非安全整数均拒绝。
- 当前版本为 `1`；高于当前版本时报错并提示升级插件，绝不尝试降级或静默使用默认配置。
- 版本不是用户可热编辑的业务字段，不标记 `.volatile()`，不出现在白名单表单中。修改原始版本标识走 Loader 普通重建生命周期。
- 用户不需要给现有配置补版本；新写的完整配置建议显式标记实际格式版本。安装 Bundle 不强加版本标记，避免把继承标记误当作用户配置已经迁移的证据。

## 执行流程

```text
宿主组合配置并求值 → 检查版本 → 克隆输入
  → v0→v1→…逐步迁移 → 完整 Config 校验 → Loader 提交运行时配置
```

[迁移实现](<../src/config-migrations.ts>)维护 `CONFIG_SCHEMA_VERSION` 和以源版本为键的迁移表。每一步只能前进一个版本，缺少迁移步骤或未正确推进版本均报错。迁移函数只处理原始普通值，不读写磁盘、不访问网络、不添加业务默认值。输入经过深克隆，因此迁移、校验失败都不会修改调用者的对象。保留未知字段和显式空数组，尤其不能将撤销授权的 `[]` 删除或替换成继承值。

[插件入口](<../src/index.ts>)同时覆盖直接 `Config(raw)`、Cordis 的 `Config["~standard"].validate(raw)` 和 `createProvider(raw)`。`migrateConfig(raw)` 导出供组合代码使用，但它只迁移格式，不代表业务校验成功；完整校验应调用 `Config` 或宿主 `resolveConfig`。

包装器保留对象 schema 的 `type`、`dict`、序列化能力和字段 volatile 元数据。不能简单把根 schema 改成 transform：宿主 Settings 依靠对象结构投影表单，Loader 也依靠字段信息判定热更新。序列化后的浏览器 schema 不执行迁移，Host 校验才是权威边界。外部代码应调用公开 `Config`，不要重新构造其 JSON schema 后假定仍有 Host 迁移能力。

## 失败与持久化边界

运行时归一化不会更新 Loader 的原始 entry 配置，也不会自动给 Web 保存结果添加版本字段。重复启动可重复执行纯迁移，结果幂等；v0→v1 无字段改名，所以现有保存和恢复继承行为保持不变。

配置版本不合法时首次加载失败。Host 配置编辑器会在持久化前校验，失败不应落盘；直接手动修改文件绕过编辑器时，Loader 会保留文件中的原始值。若改动包含非 volatile 字段（如版本），可能重建并停止旧实例，**不承诺所有无效手工改动都保留旧实例**。普通 volatile 候选校验失败时，现有 Loader 行为仍保留运行中的引用，不部分提交。

不在 `apply()` 中调用写文件或递归更新 entry：此时已完成配置解析，且插件看到的可能是多个层的组合结果，写回会固化继承值、干扰 HMR，甚至扩大授权。此次实现不声称已完成磁盘格式的自动升级。

## 后续新增 v2 的步骤

1. 将当前格式版本增加到 2，保留 v0→v1，新增迁移表的 `1` 项，返回 `schemaVersion: 2`。
2. 为重命名、单位变化、字段拆分制定明确规则；新旧字段同时出现时明确优先级或拒绝歧义，不能猜测用户授权意图。
3. 更新当前业务 schema、示例和测试，覆盖所有历史版本直升当前版本、幂等、输入不变、失败及未来版本拒绝。
4. **若字段发生改名，必须同步设计表单写入及分层持久化迁移，不能只加一个读取转换。**旧原始字段与新表单字段共存时，恢复继承可能重新激活旧值。混合版本的层也不能仅凭最终一个版本标记判断所有字段来源。
5. 如需落盘，由宿主在知道配置来源的边界内执行：按层迁移 → 校验组合结果 → revision/CAS 与文件锁 → 保留可恢复副本 → 原子写入 → Loader reconcile；失败回滚。只处理拥有写权限的目标层，保留未知字段、表达式与覆盖语义，不把运行时默认值或求值后的表达式写回。

任何改变授权范围且无法证明语义等价的迁移，都应拒绝自动处理或要求用户确认。“无感”不应凌驾于安全和可恢复性之上。
